title: Streaming responses
description: Read Server-Sent Events or newline-delimited JSON as a Stream, and handle how a stream fails or stops.

Some APIs send their answer a piece at a time: progress feeds,
notifications, exports, the answers of language models. Waiting for the
whole body would mean showing nothing until the end. `api.sse` and
`api.ndjson` give such a body as an Effect `Stream`, one value at a time,
as it arrives. This page shows how to read both formats, define stream
endpoints, and handle a stream that fails or that you stop.

## Read Server-Sent Events

`api.sse` reads a `text/event-stream` body. Each value is an event, with
its `event` name (`"message"` when the server sends none), its `id`, and its
`data`, decoded with `output`:

```ts
import * as Effect from "effect/Effect";
import * as Schema from "effect/Schema";
import * as Stream from "effect/Stream";

import type { Fetch } from "@monarcode/effetch";

declare const api: Fetch.Client;

const JobEvent = Schema.Struct({ percent: Schema.Finite });

export const followJob = (id: number) =>
  api.sse("/jobs/:id/events", { params: { id }, output: JobEvent }).pipe(
    Stream.takeUntil((event) => event.data.percent === 100),
    Stream.runForEach((event) => Effect.log(`${event.data.percent}%`)),
  );
```

`output` decodes each event's `data` as JSON. Without it, or with
`Fetch.text()`, `data` is the text as it was sent.

The request is a `GET` by default. An API that streams its answer to a
request usually takes a `POST` with a body, so pass `method` and `body`:

```ts
import * as Schema from "effect/Schema";

import type { Fetch } from "@monarcode/effetch";

declare const api: Fetch.Client;

const Prompt = Schema.Struct({ prompt: Schema.String });
const Delta = Schema.Struct({ text: Schema.String });

export const complete = (prompt: string) =>
  api.sse("/completions", {
    method: "POST",
    input: Prompt,
    body: { prompt },
    output: Delta,
  });
```

The request sends `Accept: text/event-stream`, unless the call or the
client sets an `accept` header.

### How events are parsed

Events are parsed by the
[WHATWG rules](https://html.spec.whatwg.org/multipage/server-sent-events.html),
which most servers follow without you noticing. A few of them can surprise
you:

- Comment lines are ignored. A multi-line `data` is joined with `\n`, and
  an `id` carries over to the events after it.
- An event without any `data` line is dropped.
- An event ends at a blank line. When the server closes the connection
  without one after its last event, that last event is dropped.
- An event over 10 MiB fails the stream with a `DecodeError`.
- A response whose `Content-Type` is set to a type other than
  `text/event-stream`, such as a login page from a proxy, fails the stream
  with a `DecodeError` before any event.
- The stream doesn't reconnect, and ignores `retry:` lines.

[Limitations](/docs/reference/limitations#streams) shows how to pick up a
stream where it stopped.

<Callout>
  `api.sse` parses events with Effect's `encoding/Sse` module, which Effect
  marks unstable.
</Callout>

### Stop at a sentinel

`output` decodes every event, so an event whose data doesn't match it fails
the stream, after the events before it. Some servers end with a sentinel
that isn't JSON, such as `data: [DONE]`. For those, leave `output` out,
stop at the sentinel, then decode the rest:

```ts
import * as Schema from "effect/Schema";
import * as Stream from "effect/Stream";

import type { Fetch } from "@monarcode/effetch";

declare const api: Fetch.Client;

const Delta = Schema.fromJsonString(Schema.Struct({ text: Schema.String }));

export const deltas = (prompt: string) =>
  api.sse("/completions", { method: "POST", body: { prompt } }).pipe(
    Stream.takeWhile((event) => event.data !== "[DONE]"),
    Stream.mapEffect((event) => Schema.decodeUnknownEffect(Delta)(event.data)),
  );
```

## Read newline-delimited JSON

`api.ndjson` reads an `application/x-ndjson` body, also called JSON Lines:
one JSON value per line, each decoded with `output`:

```ts
import * as Schema from "effect/Schema";
import * as Stream from "effect/Stream";

import type { Fetch } from "@monarcode/effetch";

declare const api: Fetch.Client;

const Row = Schema.Struct({ id: Schema.Finite, email: Schema.String });

export const countRows = api
  .ndjson("/export/users", { output: Row })
  .pipe(Stream.runCount);
```

The following rules apply to an NDJSON call:

- Without `output`, each value is the parsed JSON, typed `unknown`.
  `Fetch.text()` gives each line's text instead.
- Blank lines are skipped, and the last line needs no line end.
- The request sends `Accept: application/x-ndjson`, unless an `accept`
  header is set.
- Unlike SSE, the response's `Content-Type` isn't checked. A body that
  isn't NDJSON, such as an HTML page, fails on its first line as invalid
  JSON, unless you read the lines as text with `Fetch.text()`.

## Define a stream endpoint

An [endpoint](/docs/endpoints) defined with `stream: "sse"` or
`stream: "ndjson"` returns a `Stream` from its calls, however it's bound:

```ts
import * as Effect from "effect/Effect";
import * as Schema from "effect/Schema";
import * as Stream from "effect/Stream";

import { Fetch } from "@monarcode/effetch";

const JobEvent = Schema.Struct({ percent: Schema.Finite });

const jobEvents = Fetch.endpoint("GET /jobs/:id/events", {
  output: JobEvent,
  stream: "sse",
});

class Api extends Fetch.Service<Api>()("Api", {
  baseUrl: "https://api.example.com",
}) {}

export class JobApi extends Fetch.Endpoints<JobApi>()("JobApi", Api, {
  events: jobEvents,
}) {}

export const lastEvent = (id: number) =>
  Effect.gen(function* () {
    const jobs = yield* JobApi;
    return yield* jobs.events({ params: { id } }).pipe(Stream.runLast);
  });
```

Its calls follow the same rules as `api.sse` or `api.ndjson`.

## How a stream fails

A stream fails in two stages: while its request is sent, and while its body
is read.

The request runs as any call does, up to the response's headers:

- Plugins run once. `retry` and `timeout` apply to getting the response,
  not to reading the body.
- When no response arrives, the stream fails with a `NetworkError`.
- A plugin's error fails it too, such as the `TimeoutError` of the
  `timeout` plugin.
- An error status fails it with an `HttpError`, or a
  [`statusErrors`](/docs/errors/status-errors) error, before it gives any
  value.
- A `204 No Content` or `205 Reset Content` gives an empty stream.

Then the body is read as it arrives, and the values before a failure are
given first. A value that doesn't match `output`, or a body that breaks
off, fails the stream with a `DecodeError`, which names the event or the
line, as in `Line 3 doesn't match the output schema`.
On React Native, the built-in `fetch` doesn't stream response bodies, so
every stream fails there with a `DecodeError`.
[Platform notes](/docs/platforms#react-native) shows which `fetch` to use
instead.

For plugins, a stream's call ends when the response's headers arrive:

- `logger` times every call up to the headers, so for a stream, it logs the
  time to the headers.
- `onExit` hooks, `consoleLogger`'s among them, run when the headers
  arrive, and report the time to the headers.
- A `DecodeError` while the body is read reaches neither.

Handle errors from the body on the stream itself, with
`Stream.catchTag("DecodeError", …)` or `Stream.tapError`.

## Stop a stream

Interrupting the stream, or taking only part of it, as with `Stream.take`,
aborts the request. You don't need to close the connection yourself.

## Options a stream doesn't take

A stream can't take `responseMode`, since it gives the body's values, or an
`output` made with `Fetch.bytes()`, which can't decode them one at a time.
A call that passes one dies, and a definition with one throws when it's
made.
